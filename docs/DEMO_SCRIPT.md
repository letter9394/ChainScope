# ChainScope 3–5 分钟演示脚本

## 演示前检查

1. 打开 [线上站点](https://chainscope-web3.onrender.com/)；免费实例首次唤醒可能需要约 50 秒。
2. 打开 [`/api/health`](https://chainscope-web3.onrender.com/api/health)，确认 `status` 为 `ok`。
3. 使用演示账号登录并确认邮箱已验证；不要在录屏中展示密码、API Key 或 Render 环境变量。
4. 预先创建一条容易触发的临时规则，例如 BTC 综合风险分 `≥ 0`，完成演示后删除。

## 0:00–0:40 项目定位

建议讲法：

> ChainScope 不是交易终端，而是一个把实时市场数据、可解释风险分析、历史验证和用户预警串起来的全栈作品。当前覆盖 BTC、ETH、SOL 和现货黄金。

展示：四张资产卡片，以及行情从 WebSocket 实时变化。

## 0:40–1:30 K 线与数据可靠性

1. 点击 BTC，切换 1 分钟、1 小时和日线。
2. 打开 MA、BOLL、MACD、RSI，移动十字光标查看历史 OHLC。
3. 点击 XAU，说明黄金默认使用 TradingView 的 OANDA XAU/USD；网络受限时可以切换站内 PAXG 实时代理或 Massive 延迟历史。

关键解释：图表标题和当前价始终跟随图表自己的数据源，避免把不同报价口径误认为同一个实时价格。

## 1:30–2:20 风险模型与回测

1. 返回 BTC，展示风险总分和每个指标贡献。
2. 展示资金费率、持仓量、多空比、恐慌贪婪和页面实时强平。
3. 滚动到“高风险信号回测”，说明 3 年样本、30 日滚动窗口、未来 1/3/7 日最大跌幅、市场基准与 Lift，以及带 7 日标签隔离的 Walk-forward 验证。
4. 在“跨资产晋级审查”中切换 BTC、ETH、SOL，对比各自基准、精确率和 Lift；说明单资产通过仍不够，至少两个资产完整达标才允许进入影子运行。
5. 展示 v0.3 与 v0.4 特征模型对照，说明项目不会因为模型更复杂就自动上线；未超过留出期基准时会明确拒绝晋级。
6. 展示 v0.5 标签实验，比较固定跌幅、波动率归一化和训练集分位数标签，解释 Brier Score 与 ECE 越低代表概率越可信、Brier Skill 用来公平比较不同事件率；再指出 14 日区块 Bootstrap 的 95% 区间用于识别小样本偶然性，Lift 下界未超过 1 时不会晋级。
7. 展示 v0.6 跨周期稳定性审查，说明同一种替代标签必须同时通过 3 日与 7 日窗口，任何一个周期不稳定都会阻止进入跨资产影子运行。
8. 展示 v0.7 时间稳定性与漂移监控，对比三轮连续留出期的事件率、精确率、Lift 和 Brier Skill；强调“性能衰减”是复核告警，不是行情方向信号，也不会自动换模。

关键解释：实时衍生品没有可靠历史快照，所以不纳入历史回测；Walk-forward 调参也会隔离预测窗口，避免标签穿越和前视偏差。

## 2:20–3:20 用户预警闭环

1. 登录演示账号。
2. 创建 BTC 综合风险分 `≥ 0` 的临时规则。
3. 点击立即检查，展示站内事件。
4. 打开手机邮箱中的风险提醒邮件。
5. 确认事件并删除临时规则。

关键解释：系统只在“安全 → 越线”时产生事件；持续越线不会每 60 秒重复发信。

## 3:20–4:10 安全与工程质量

建议讲法：

> 用户密码使用 scrypt 加盐哈希，会话存放在 HttpOnly Cookie。新账号需要邮箱验证；认证端点有 IP 与账号双维度限流，所有写请求还有签名 CSRF Token。后端有 96 项自动化测试，前端用 Playwright 覆盖关键交互。

展示：GitHub Actions 或 README 测试命令，不展示任何密钥页面。

## 4:10–5:00 部署与可观测性

展示 `/api/health`：

- `version` 对应 Git 提交；
- `database` 显示连接状态和延迟；
- `scheduler` 显示最近一轮耗时、用户数和事件数；
- `email` 显示 Brevo 是否可用。

收尾建议：

> 这个项目最重要的不是页面数量，而是我把外部数据不稳定、报价口径、历史验证、用户状态、安全和线上运维当成一个完整系统来处理。

## 录屏交付建议

- 分辨率：1920×1080，浏览器缩放 90%–100%。
- 时长：控制在 5 分钟内，前 15 秒直接展示成品。
- 隐私：隐藏书签栏、邮箱地址、Render 控制台和所有 Key。
- 视频文件不提交 Git；上传到可分享平台后，在 README 中添加链接和封面图。
