# ChainScope 3–5 分钟演示脚本

## 演示前检查

1. 打开 [线上站点](https://chainscope-web3.onrender.com/)；免费实例首次唤醒可能需要约 50 秒。
2. 打开 [`/api/health`](https://chainscope-web3.onrender.com/api/health)，确认 `status` 为 `ok`。
3. 使用演示账号登录，确认邮箱已验证且账户页的“邮件通知”已开启；不要在录屏中展示邮箱地址、密码、API Key 或 Render 环境变量。
4. 演示前不要保留重复的 `≥ 0` 测试规则；录屏时只创建一条，避免误以为系统重复告警。完成演示后先保存证据，再删除临时规则。
5. 先录一遍不公开的试拍，确认页面与邮件中没有个人信息；正式视频只展示可公开的页面和脱敏证据。

## 0:00–0:40 项目定位

建议讲法：

> ChainScope 不是交易终端，而是一个把实时市场数据、可解释风险分析和用户预警串起来的全栈作品。当前覆盖 BTC、ETH、SOL 和现货黄金。

展示：四张资产卡片，以及行情从 WebSocket 实时变化。

## 0:40–1:30 K 线与数据可靠性

1. 点击 BTC，切换 1 分钟、1 小时和日线。
2. 打开 MA、BOLL、MACD、RSI，移动十字光标查看历史 OHLC。
3. 点击 XAU，说明黄金默认使用 TradingView 的 OANDA XAU/USD；网络受限时可以切换站内 PAXG 实时代理或 Massive 延迟历史。

关键解释：图表标题和当前价始终跟随图表自己的数据源，避免把不同报价口径误认为同一个实时价格。

## 1:30–2:20 当前风险与市场背景

1. 返回 BTC，展示风险总分和每个指标贡献。
2. 展示资金费率、持仓量、多空比、恐慌贪婪和页面实时强平。
3. 解释当前风险分为何变化，以及它与资金费率、持仓量和市场情绪是否一致；不要把评分表述为交易建议。
4. 点击预警区，让观众看到如何把当前风险转成自己可设置的提醒。

关键解释：历史模型实验仍保留在后台研究接口，但不占用普通用户首页，也不应把未经验证的实验结果说成预测能力。

## 2:20–3:20 用户预警闭环

1. 登录演示账号。
2. 创建 BTC 综合风险分 `≥ 0` 的临时规则；保存后页面会自动首次检查，展示新产生的站内事件。
3. 展示收到的风险提醒邮件，遮住邮箱地址和其他个人信息。
4. 再点一次“立即检查”，展示“本次没有新增预警”；然后点击“我知道了”，说明确认事件不会让同一越线状态再次通知。
5. 录屏或截图留证后删除临时规则；删除规则也会删除对应事件历史。`0` 分只用于可重复验收，不是建议的日常报警线。

关键解释：系统只在“安全 → 越线”时产生事件；持续越线不会每 60 秒重复发信。

## 3:20–4:10 安全与工程质量

建议讲法：

> 用户密码使用 scrypt 加盐哈希，会话存放在 HttpOnly Cookie。新账号需要邮箱验证；认证端点有 IP 与账号双维度限流，所有写请求还有签名 CSRF Token。后端有 119 项自动化测试，前端有 13 个 Playwright 端到端流程。

展示：GitHub Actions 或 README 测试命令，不展示任何密钥页面。

## 4:10–5:00 部署与可观测性

展示 `/api/health`：

- `version` 对应 Git 提交；
- `database` 显示连接状态和延迟；
- `scheduler` 显示最近一轮耗时、用户数和事件数；
- `risk_drift` 显示最近一次三资产模型复查、迁移事件数和失败资产数；
- `email` 显示 Brevo 是否可用。

补一句：生产数据库已迁到 Neon，GitHub Actions 每日加密备份，并在另一个任务中下载、隔离恢复验证；免费 Web Service 休眠期间不能保证预警持续运行。只展示成功任务的页面，不打开 Secrets 或数据库连接信息。

收尾建议：

> 这个项目最重要的不是页面数量，而是我把外部数据不稳定、报价口径、历史验证、用户状态、安全和线上运维当成一个完整系统来处理。

## 录屏交付建议

- 分辨率：1920×1080，浏览器缩放 90%–100%。
- 时长：控制在 5 分钟内，前 15 秒直接展示成品。
- 隐私：隐藏书签栏、邮箱地址、Render 控制台和所有 Key。
- 视频文件不提交 Git；上传到可分享平台后，在 README 中添加链接和封面图。
